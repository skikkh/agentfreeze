# AgentFreeze lockfile format v1

Status: reference format
Version: 1
Normative keywords: MUST, MUST NOT, SHOULD, MAY are interpreted as in RFC 2119.

## Purpose and boundary

`agentfreeze.lock` records the exact observed state of AI agent extensions installed under the
user's home and host-specific config locations. The only lock scope in v1 is `user`.

The v1 file is an integrity baseline. It is not an installer, dependency resolver, safety verdict,
runtime policy, or proof of origin.

[Seal](https://sealfile.dev/) specifies project-local bundle authorization and native load-time
behavior. AgentFreeze v1 MUST NOT write a project-local authorization lockfile or claim Seal
compatibility. Implementations SHOULD recommend Seal when a user needs project-local enforcement.
An implementation MAY inventory workspace extensions for display, but MUST NOT put them in an
AgentFreeze v1 lockfile.

## File name and encoding

- The default file name MUST be `agentfreeze.lock`.
- The file MUST be UTF-8 without a byte-order mark.
- Writers MUST use LF line endings and exactly one trailing newline.
- Writers MUST serialize with two-space indentation.
- Entries MUST be sorted by `id` in ascending Unicode scalar-value order.
- `scanScopes` MUST be exactly `["user"]`.
- Readers MUST reject duplicate or unsorted entry IDs.

The Rust reference implementation's struct field order is canonical:

1. `$schema`
2. `lockfileVersion`
3. `generatedBy`
4. `scanScopes`
5. `entries`

Within an entry:

1. `id`
2. `ecosystem`
3. `kind`
4. `scope`
5. `name`
6. `source`
7. optional `version`
8. optional `revision`
9. `digest`
10. `files`
11. `bytes`
12. `symlinks`

## Top-level fields

| Field | Required | Meaning |
|---|---:|---|
| `$schema` | yes | Canonical v1 JSON Schema URL |
| `lockfileVersion` | yes | Integer `1` |
| `generatedBy` | yes | Writer identity, currently `agentfreeze <semver>` |
| `scanScopes` | yes | Exactly `["user"]` in v1 |
| `entries` | yes | Sorted extension records |

## Entry identity

An entry ID has four conceptual fields:

```text
<ecosystem>:<kind>:<scope>:<source>
```

The source is a portable locator. Because v1 lockfiles contain only user-scoped entries, every
lockfile source MUST be `$HOME` or begin with `$HOME/`. Workspace inventory output MAY use
`$WORKSPACE`, but it MUST NOT be written to a v1 lockfile. JSON/TOML subresources append a
JSON-Pointer-like fragment:

```text
codex:mcp-server:user:$HOME/.codex/config.toml#/mcp_servers/example
```

`~` and `/` in a configuration entry name are escaped as `~0` and `~1`.
Readers MUST reject an entry whose `id` does not exactly match its serialized `ecosystem`, `kind`,
`scope`, and `source`.

## Path-content digest

The digest uses SHA-256 over a length-prefixed byte stream. `field(x)` means:

```text
u64_big_endian(byte_length(x)) || x
```

The stream begins with:

```text
field("agentfreeze-path-v1")
```

Directory contents are visited recursively. Records are sorted by normalized UTF-8 relative path,
then record kind. Separators are `/`.

For a directory:

```text
field("directory") || field(relative_path)
```

For a regular file:

```text
field("file") || field(relative_path) || field(u64_big_endian(file_size)) || raw_file_bytes
```

For a symbolic link inside an extension:

```text
field("symlink") || field(relative_path) || field(normalized_link_target)
```

All regular files and directories are included, including `.git`, `.DS_Store`, and other dotfiles.
The format has no ignored-name list because an extension can read or materialize payloads from
normally hidden locations.

Paths and link targets MUST be valid UTF-8. Special files MUST make the scan fail. A symlink used as
the extension root MUST make the scan fail. An internal symlink MUST be hashed as a link record and
MUST NOT be followed. The bytes behind an internal symlink are covered only when its target is also
a regular file inside the same scanned extension tree.

Plugin-manifest discovery MUST NOT silently omit a plugin directory reached through a symlink. A
broken link or a link resolving outside the canonical plugin discovery root MUST fail the scan. An
internal directory alias MUST be resolved inside that root and traversed using the alias's logical
depth. Discovery MUST deduplicate canonical targets, revisit a target reached with a shallower
logical depth, and fail on cycles or a link that would exceed the discovery depth limit. A symlink
at a plugin-manifest file path is unsupported and MUST fail the scan.

The output string is:

```text
sha256:<64 lowercase hexadecimal characters>
```

`files` is the number of hashed regular files. `bytes` is their total size. `symlinks` is the
number of hashed internal link records.

## MCP-definition digest

Known JSON MCP configuration files MUST have an object at the document root. When a supported
`mcpServers`, `servers`, `projects`, or project-level `mcpServers` key is present, its container
MUST be an object. In Codex TOML, a present `mcp_servers` container and every server definition
MUST be a table. JSON server definitions MUST be objects. A missing supported key means no
definitions in that location; a present key with the wrong type MUST fail discovery.

MCP definitions are converted to JSON and sanitized before hashing:

- each known configuration file MUST resolve inside its owning boundary before it is read: user
  configuration inside the canonical home directory and workspace configuration inside the
  canonical workspace; broken links and boundary escapes MUST fail the scan
- object keys are sorted
- workspace and home path prefixes become `$WORKSPACE` and `$HOME`
- likely secret-key fields, including environment and HTTP-header children, are replaced with
  `"<redacted>"`
- values following secret-like CLI flags are replaced with `"<redacted>"`
- URL user information and fragments are replaced with `"<redacted>"`
- query values are replaced only when their key is secret-like; non-secret routing values remain

Secret-like names include password, passphrase, token, session, PAT, secret, cookie, authorization,
credential, API-key, private-key, access-key, auth, and bearer forms. A field ending in `_env_var`
records the environment-variable name, not its value, and is not itself redacted. URL handling
applies to URL/URI/DSN/endpoint fields and URL-like CLI arguments.

The digest stream is:

```text
field("agentfreeze-mcp-v1") || field(canonical_sanitized_json)
```

MCP secret rotation is intentionally outside drift detection when the changed value is redacted.
A tenant or account change encoded only inside such a credential is therefore also outside v1.
Non-secret tenant, account, region, endpoint, and mode values MUST remain in the sanitized form.
The lockfile MUST NOT contain the unsanitized definition.

## Verification

The verifier MUST scan the user scope. A v1 reader MUST reject any other `scanScopes` value.

- `clean`: every locked entry is present and unchanged; no untracked entry exists
- `modified`: the digest, version, or revision differs
- `missing`: a locked ID is absent
- `untracked`: an observed ID is not locked

`--allow-untracked` MAY suppress `untracked` findings; it MUST NOT suppress modified or missing
findings.

Exit codes:

- `0`: clean
- `1`: drift
- `2`: invalid lockfile, incomplete scan, parse error, or other operational failure

## Conformance

Passing the JSON Schema is necessary but not sufficient. A conforming implementation MUST also
enforce canonical ordering, ID uniqueness, hash construction, redaction, fail-closed discovery,
and verification outcomes.

AgentFreeze will not describe v1 as an industry standard until an independent implementation
passes shared positive and negative fixtures.
